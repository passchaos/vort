# ZIP32 archive support

Vort provides dependency-free, library-first reading and deterministic writing
for common single-disk ZIP32 archives. The reader parses the
end-of-central-directory record and central directory before exposing entries,
so data-descriptor archives use the authoritative sizes and CRC values instead
of trusting incomplete local headers.

Supported entry methods:

- stored (`method 0`);
- raw Deflate (`method 8`) through the same decoder used by Vort's public raw,
  zlib, and gzip APIs.

The decoder validates local/central method and filename agreement, exact
compressed and uncompressed sizes, complete Deflate consumption, and IEEE
CRC-32. It supports the general-purpose data-descriptor flag with or without a
descriptor signature because extraction boundaries come from the central
directory.

The writer accepts multiple borrowed entries, emits stored or raw-Deflate
members, and records CRC-32, sizes, entry comments, an archive comment, and the
UTF-8 general-purpose flag. Its fixed DOS timestamp is `1980-01-01 00:00:00`,
so identical inputs and options produce identical bytes. Data descriptors are
optional and include the standard descriptor signature when enabled.

```zig
const entries = [_]vort.ZipEncodeEntry{
    .{ .name = "plain.bin", .data = plain, .method = .stored },
    .{ .name = "folder/data.txt", .data = text, .method = .deflate },
};
const zip_bytes = try vort.zipEncodeAlloc(allocator, &entries, .{
    .archive_comment = "generated by Vort",
    .data_descriptor = true,
});
defer allocator.free(zip_bytes);
```

`zipEncodeAppend` builds the archive transactionally: an error leaves the
destination length and bytes unchanged. When the destination already contains
bytes, they are treated as a self-extracting prefix and all stored ZIP offsets
include that prefix.

```zig
const archive = try vort.parseZipArchive(zip_bytes);
defer allocator.free(try archive.entriesAlloc(allocator));

const entry = (try archive.find("folder/data.txt")) orelse
    return error.ZipEntryNotFound;
const decoded = try archive.extractAllocLimited(
    allocator,
    entry,
    64 * 1024 * 1024,
);
defer allocator.free(decoded);
```

Convenience functions `zipExtractEntryInto`, `zipExtractEntryAlloc`,
`zipExtractEntryAllocLimited`, `zipExtractByNameAlloc`, and
`zipExtractByNameAllocLimited` parse and extract in one call. Entry names are
returned as borrowed archive bytes. Vort never automatically joins an entry
name to a filesystem path; callers therefore retain explicit control over
Zip-Slip/path-traversal policy.

CLI validation surfaces:

```sh
zig build run -- list-zip-file archive.zip
zig build run -- extract-zip-file archive.zip folder/data.txt output.txt 67108864
zig build run-zip-diff
```

The writer rejects empty names, invalid UTF-8 names/comments when UTF-8 mode is
enabled, ZIP32 sentinel sizes/counts/offsets, and methods other than
stored/Deflate. The reader deliberately rejects encrypted entries, multi-disk
archives, ZIP64 sentinel fields, and compression methods other than
stored/Deflate with specific errors. Those are explicit future compatibility
increments rather than silently accepted partial behavior.
