# Wiimms WDF and WDF2 images

Vort provides a pure-Zig reader and deterministic writer for Wiimms Disc File
versions 1 and 2. WDF is a sparse image container: stored chunks contain file
data while gaps in the virtual image are reconstructed as zeroes.

Both versions use the same 56-byte big-endian header. WDF1 uses 28-byte chunk
entries with an obsolete split-file index; WDF2 removes that field and uses
24-byte entries. The reader validates version compatibility, header and chunk
table magic, alignment, exact physical size, sorted non-overlapping logical
ranges, physical extents, stored-size accounting, table separation, and
caller-configured limits.

```zig
var image = try vort.parseWdfAlloc(allocator, wdf_bytes, .{
    .max_chunks = 1 << 24,
    .max_parts = 100,
    .max_alignment = 1 << 30,
});
defer image.deinit();

const range = try image.readRangeAllocLimited(
    allocator,
    offset,
    length,
    max_output,
);
defer allocator.free(range);
```

Callers can provide split WDF files as ordered byte slices:

```zig
var image = try vort.parseWdfPartsAlloc(
    allocator,
    &.{ first_part, second_part, third_part },
    .{},
);
defer image.deinit();
```

The writer scans 4-byte words, omits sufficiently large all-zero runs, packs
stored chunks directly after the header, and appends the version-specific chunk
table. A partial final word is zero-padded while the header retains the exact
logical size. WDF2 is the default.

```zig
const wdf = try vort.encodeWdfAlloc(allocator, image_bytes, .{
    .version = .v2,
    .sparse_zeroes = true,
    .min_hole_size = 28,
    .max_output_len = limit,
});
defer allocator.free(wdf);
```

CLI and validation surface:

```sh
zig build run -- inspect-wdf image.wdf
zig build run -- decode-wdf image.wdf image.iso 9399959552
zig build run -- decode-wdf-range image.wdf range.bin 1048576 65536
zig build run -- encode-wdf image.iso image.wdf wdf2 sparse 28
zig build test-wdf
zig build run-wdf-diff
```

The differential compares WDF1/WDF2 sparse and full writer output byte-for-byte
with an independent Python implementation. Wiimms `wdf` must decode all four
outputs, while Vort must decode WDF1 and WDF2 generated by `wit --raw`.

Current explicit limitations are writer-side split output and filesystem-aware
Wii scrubbing. The library reads split inputs when the caller supplies their
byte slices; the writer's zero-run detection is format-correct but intentionally
simple. Streaming file I/O and more advanced sparse scanning remain follow-up
work.
