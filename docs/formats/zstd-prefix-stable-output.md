# Zstd prefix lifetime and stable caller output

Zstd prefixes provide a single-use dictionary binding. Stable output permits a
decoder to use already generated caller-owned bytes as its match history. Both
features retain explicit ownership, ordinary frame validation and the existing
dictionary/checksum controls.

## Prefix binding

`DictionaryUsage` distinguishes `persistent` dictionaries from `prefix`
bindings. The default remains persistent. `FrameOptions`, `NativeFrameOptions`,
`FrameDecodeOptions` and incremental decode options carry `dictionary_usage`;
existing dictionary arguments identify the actual RAW or full dictionary.
RAW prefix convenience APIs construct ID-less raw-content dictionary views.
Advanced prefix dictionary methods preserve standard entropy tables and the
real dictionary identity.

The package root names these contracts `ZstdDictionaryUsage`,
`ZstdPrefixPhase`, `ZstdPrefixPurpose`, `ZstdPrefixContentType` and
`ZstdPrefixSnapshot`. Its `zstd*WithPrefix*` functions provide the RAW-prefix
one-shot facade; reusable and incremental `Zstd*` types expose the lifecycle
methods directly.

Reusable and incremental handles expose `setPrefix(bytes)`,
`setPrefixWithDictionary(dictionary)`, `clearDictionary()` and
`prefixSnapshot()`. A new prefix replaces the old prefix or persistent
dictionary. Consuming it does not restore an earlier dictionary. Empty bytes
clear the binding. Borrowed prefix bytes remain immutable until their active
use completes or the operation ends with an error/reset/deinitialization.
Mutation eligibility and prefix consumption are separate state dimensions.

The local libzstd 1.6.0 reference audit establishes these boundaries:

| Operation | Prefix consumption |
| --- | --- |
| One-shot decode | Select once for the entire call, including joined frames; an empty or failed call consumes the selection. |
| Incremental decode | Accepting the first complete frame header consumes it, including a standard skippable frame. |
| Incremental encode | Initializing the stream consumes it, including an empty initial processing call. |
| Session reset before consumption | Retains the pending prefix. |
| Session reset after consumption | Does not restore it. |
| Parameter/all reset | Clears dictionaries and prefixes. |

An incremental bad/partial header can leave a pending prefix intact, while
payload and checksum errors occur after consumption. A failed stream still
requires an appropriate reset before mutation. One-shot joined skippable/data
input differs from separate skippable and data calls. Magicless mode parses
standard skippable bytes as magicless data rather than recognizing a skippable
frame. These distinctions are recorded by actual reference execution, rather
than inferred from the phrase "next frame".

Dictionary catalogs cannot infer an ID-less RAW prefix. An explicitly chosen
full dictionary can retain its real ID while the independent
`include_dictionary_id` option controls header serialization.

## Stable output

An incremental decoder can bind a complete mutable buffer with
`bindStableOutput(buffer)`, then use `stepStable(input)` or
`stepStableLimited(input, max_output)` while the decoder maintains output
positions. `stableOutput()` exposes the published prefix;
`nextStreamWithStableOutput(buffer)` provides separate storage for a resumed
member. At an idle frame boundary, `clearStableOutput()` releases the binding
without changing cumulative counters, so the same decoder can resume ordinary
caller-selected output slices through `step`. Rebinding or clearing while a
frame is active is rejected. The ordinary caller-output `step` path otherwise
retains its existing behavior.

The binding stores the buffer and local frame positions. Logical cumulative
counts remain `StreamCount`; converting cumulative output totals to a local
buffer index would break 32-bit multi-frame streams. Active buffers and already
published bytes remain stable during use. Rebinding during an active frame is
rejected before input or published output changes.

Available history remains the format's validated dictionary plus the window-
limited generated frame prefix. Unwritten buffer capacity contributes no
history, and older addressable caller bytes cannot enlarge legal distances.
Reads that reach before current-frame output use the selected prefix/dictionary
span. A prefix that would be overwritten by the output binding is rejected;
an earlier frame used as the next prefix requires nonoverlapping output storage.

Known content size is checked against capacity before payload writes. Unknown
sizes use block admission and preserve correct failure progress. A buffer filled
exactly to capacity still permits EOB/footer completion. Direct/block streaming
publishes generated bytes through normal progress accounting. Prevalidated
decoding stages into the unexposed caller region and publishes after validation;
an error preserves already published bytes, while unexposed storage may contain
staging writes.

The stable path releases retained owned output/history when switching modes.
It still accounts for compressed input and required entropy scratch. Heap
evidence measures decoder-owned requested allocations and retained capacities,
not process RSS.

## Reference and platform validation

The reference tools live in `tools/zstd/prefix_lifecycle/` and
`tools/zstd/stable_output/`. They retain actual commands, loaded library/header
and probe hashes, RAW/FULL dictionary choices, frame/byte progress, reset/error
boundaries and output-storage observations. The reference library must support
`ZSTD_CCtx_refPrefix`, `ZSTD_DCtx_refPrefix` and `ZSTD_d_stableOutBuffer` (1001).

Run native, x86 and WASI contracts and bounded reference matrices:

```sh
zig build -j2 test-zstd-prefix-lifecycle
zig build -j2 test-zstd-stable-output
zig build -j2 test-zstd-prefix-stable-public
# Append -x86 or -wasm to each test step for those execution targets.
zig build -j2 run-zstd-prefix-lifecycle-preflight-diff
zig build -j2 run-zstd-stable-output-preflight-diff
# Remove -preflight for the complete bounded matrix.
```

Contracts cover standard/magicless, raw/RLE and real Huffman/FSE sequence
blocks, exact/insufficient output, zero output quanta, RAW/FULL prefixes,
dictionary recovery, checksum policy, borrowed-range rejection, warmed mode
switches, allocation failure and wide cumulative-count models.
