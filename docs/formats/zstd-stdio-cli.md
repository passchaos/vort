# Zstd CLI standard streams

## Decoding

`decode-zstd-native-file-to` accepts `-` for either endpoint. Use `./-` to
address a file literally named `-`.

```sh
vort decode-zstd-native-file-to - - < data.zst > data.bin
vort decode-zstd-native-file-to data.zst - 1048576 --max-window-size=8388608
vort decode-zstd-native-file-to - data.bin < data.zst
```

When either endpoint is `-`, the command uses the library's block-streaming
incremental decoder. It accepts concatenated Zstd frames and skips skippable
frames, with no whole-file input limit. A short pipe read can produce output
without waiting for the buffer to fill or for stdin to close. History is
bounded by the admitted window; the default advertised-window limit is
128 MiB. `--max-window-size` overrides that limit, and the optional
`max_output` counts decoded bytes across the whole stream.

When stdout is selected it carries only decoded bytes, with no statistics or
error text. The command still checks termination and content checksums and exits
nonzero on failure. A prefix already written to stdout cannot be withdrawn.
When decoding stdin to a named file, the command is quiet on success and
replaces the destination only after the entire stream succeeds. Both named file
arguments still select the original one-shot command behavior and summary.

Run `zig build test-zstd-stdio-cli` on native and WASI for binary stdout,
pre-EOF output, mixed endpoints, concatenation, skippables, truncation,
output/window limits, and atomic file publication. When the system `zstd` CLI
is available, the gate also uses a compressed checksummed frame generated by it.

## Encoding

```sh
vort encode-zstd-native-stream-file - - < data.bin > data.zst
vort encode-zstd-native-stream-file - data.zst --stream-size=1048576 < data.bin
vort encode-zstd-native-stream-file data.bin - > data.zst
```

The streaming encoder accepts `-` for either endpoint and does not buffer the
whole input. Stdin defaults to an unknown-length frame without a content-size
field. `--stream-size=BYTES` pledges the exact stdin length and enables the
content-size field by default. Explicit `content_size=true` requires a pledge;
explicit `content_size=false` omits the field even when the pledge is checked.
A short or long stdin stream fails with `SizeMismatch`. `--stream-size` is
valid only for stdin on the streaming command. Regular file input still uses
its measured size when content-size metadata is enabled.

`--max-input-len` and `--max-output-len` apply independently of the pledge, and
all three byte counts stay 64-bit. Stdout contains the compressed frame only;
requested `--profile` and `--memory-profile` reports go to stderr whenever an
endpoint is `-`. A named destination is replaced only after successful
encoding, including the length check. Previously emitted stdout bytes cannot
be withdrawn. Two named paths keep the original stream-file behavior.

`zig build test-zstd-encode-stdio-cli` verifies native and WASI encoding,
pre-EOF block output, size fields, limits, and failed-output preservation.
When available, upstream `zstd` independently decodes the generated frames.
