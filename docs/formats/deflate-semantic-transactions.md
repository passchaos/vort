# Deflate semantic token boundaries

The bounded semantic decoder can commit packed literals and then pause before
a match which does not fit the remaining generation capacity. It decodes the
complete match distance before this pause, preserving the fast loop's invalid
distance priority, and leaves the match bits unconsumed. The incremental
controller can drain the private literals and resume the same match.

The regression uses a complete dynamic literal tree with A/B at two bits,
C/EOB/length-7/length-258 at three bits, and a singleton distance-1 tree. At
32,510 generated bytes, BCA retires three more bytes before a 258-byte match.
The old 32 KiB decoder returned `OutputTooSmall`; the corrected decoder pauses
at 32,513 bytes and resumes to all 32,835 bytes.

A length/distance token can occupy 48 bits. Packed literals can leave fewer
than that staged, so the fast loop restages before decoding that token. An
additional refill may exhaust the current eight-byte load opportunity; shorter
input is left to the bounded tail. A complete 15-bit literal/distance-tree
fixture verifies the maximum token with every zero-to-sixteen-byte padding
length, including a preexisting 32 KiB dictionary prefix. Both bounded and
one-shot entrypoints must return the same content and consumed-bit count.

Focused tests are registered by `src/deflate/semantic/decoder.zig` and live in
`window_capacity_tests.zig`:

```sh
zig test -OReleaseSafe -Mroot=src/deflate.zig --test-filter 'semantic window'
```

These changes preserve the controller's private-generation transaction:
successful generations publish input progress and drain output; truncated or
malformed attempts still leave the original reader available for compact
fallback. They do not change compressed encoding or enlarge caller history.
