# 7z archive support

Vort provides a pure Zig reader for common 7z archives and a deterministic
independent/solid-folder writer. The reader supports Copy, Deflate, Bzip2,
LZMA, LZMA2, and PPMd7 folders. It also decodes bounded linear coder chains
consisting of one of those compression methods followed by Delta or x86,
PowerPC, IA64, ARM, ARM-Thumb, SPARC, ARM64, and RISC-V BCJ filters. The common
four-stream BCJ2 graph is supported with any supported compression method on
its main stream plus raw CALL, JUMP, and range-code streams, including the
standard graph in which all four packed branches have independent 7zAES
coders. The writer supports
Copy, compressed Deflate, Bzip2, LZMA1, greedy match-producing LZMA2 with a
stored fallback, and PPMd7, with the same Delta and classic BCJ filters plus
BCJ2. Compressed Next Headers and solid archives
whose files share one decoded folder stream are supported when reading.
The reader also decodes `AdditionalStreamsInfo` and resolves external folder
definitions, UTF-16LE names, creation/access/modification FILETIME values, and
raw platform attributes. The writer can keep those properties inline or place
them in separate auxiliary streams using any existing writer codec.
Common linear and four-branch BCJ2 7zAES/SHA-256 folders are supported in both
directions, including data-only encryption and encrypted encoded headers.
For large seekable archives, a source-backed reader parses through positional
reads without first materializing the complete archive. It reads the fixed
signature header, the tail Next Header, referenced external/encoded metadata,
and only the selected folder's packed ranges during extraction.
Solid writing concatenates non-empty files in archive order, applies the
selected filter chain and compressor once, and records per-file substream sizes
and CRC-32 values. Empty files and directories remain metadata-only entries.

The parser validates the 32-byte signature header and both CRC-32 fields,
7z variable-length integers, packed-stream bounds, folder and substream sizes,
folder/substream CRCs, UTF-16LE filenames, empty files, and directories.
Caller-selected limits bound Next Header and encoded-header size, individual
source-loaded packed streams, decoded external metadata, AES KDF work,
LZ/PPMd model memory, selected entry size, and the complete decoded solid
folder.

```zig
const archive = try vort.parseSevenZipArchiveAlloc(allocator, bytes);
defer archive.deinit();

const decoded = try archive.extractByNameAllocLimited(
    allocator,
    "folder/data.bin",
    64 * 1024 * 1024,
);
defer allocator.free(decoded);

const entries = [_]vort.SevenZipEncodeEntry{
    .{ .name = "folder", .kind = .directory },
    .{
        .name = "folder/data.bin",
        .data = payload,
        .modification_time = 116_444_736_030_000_000,
        .attributes = 0x81a4_0020,
    },
};
const encoded = try vort.encodeSevenZipStoredAlloc(allocator, &entries, .{});
defer allocator.free(encoded);

const filters = [_]vort.SevenZipFilter{
    vort.SevenZipFilter.x86(0),
    try vort.SevenZipFilter.delta(4),
};
const filtered = try vort.encodeSevenZipAlloc(allocator, &entries, .{
    .compression = .lzma2,
    .solid = true,
    .header_compression = .lzma2,
    .external_names = .lzma2,
    .external_metadata = .lzma2,
    .filters = &filters,
});
defer allocator.free(filtered);

const encrypted = try vort.encodeSevenZipAlloc(allocator, &entries, .{
    .compression = .lzma2,
    .solid = true,
    .header_compression = .copy,
    .encryption = .{
        .password = "correct horse 密码",
        .iv = random_iv,
        .salt = random_salt,
        .salt_len = 16,
    },
    .encrypt_header = true,
});
defer allocator.free(encrypted);

const ppmd = try vort.encodeSevenZipAlloc(allocator, &entries, .{
    .compression = .ppmd7,
    .ppmd_order = 8,
    .ppmd_memory_size = 4 * 1024 * 1024,
    .solid = true,
});
defer allocator.free(ppmd);

const source = vort.SevenZipSource{
    .context = my_source_context,
    .len = archive_file_size,
    .read_at = readArchiveAt,
};
const source_archive = try vort.parseSevenZipSourceArchiveAllocWithOptions(
    allocator,
    source,
    .{ .max_next_header_size = 16 * 1024 * 1024 },
);
defer source_archive.deinit();
const selected = try source_archive.extractByNameAlloc(allocator, "folder/data.bin");
defer allocator.free(selected);

const entry = source_archive.find("folder/data.bin") orelse return error.EntryNotFound;
var entry_decoder = try source_archive.entryDecoder(allocator, entry, .{
    .max_output_len = 64 * 1024 * 1024,
    .password = password,
});
defer entry_decoder.deinit();
while (true) {
    const stepped = try entry_decoder.step(caller_output);
    consume(caller_output[0..stepped.progress.output_written]);
    if (stepped.status == .done) break;
}
```

`SevenZipSource.read_at` receives `(context, absolute_u64_offset, output)` and
may return short reads; Vort repeats calls until the requested range is full.
The context, reported length, and underlying bytes remain borrowed and must be
stable until `SevenZipSourceArchive.deinit`. Metadata parsing does not read
ordinary file folders. The allocating extraction helpers buffer only the
selected folder's packed streams and decoded output. `entryDecoder` instead
reads packed ranges incrementally and emits caller-owned output for linear
Copy/Deflate/Bzip2/LZMA/LZMA2 folders, including AES, solid-substream prefix and
suffix discard, Delta, and all classic BCJ filters. CRC errors are reported at
the terminal step after already emitted bytes, as with conventional streaming
archive APIs. PPMd7 and branched BCJ2 still use the allocating folder path and
return `Unsupported7zFeature` from `entryDecoder` rather than silently
buffering the complete folder.

`SevenZipEncodeOptions.compression = .lzma` selects raw LZMA1 with the standard
five-byte coder properties. `.lzma2` selects literal range coding with
automatic stored fallback. Use `.lzma2_stored` when every LZMA2 chunk must be
uncompressed for diagnostics or format testing.
`.ppmd7` selects the shared pure Zig PPMd7 model. `ppmd_order` accepts 2...64
(default 6), while `ppmd_memory_size` accepts at least 2 KiB (default 16 MiB)
and is serialized little-endian in the five-byte coder properties. The model
uses checked 32-bit offsets over a 12-byte-unit suballocator, including
free-list glue and restart. 7z PPMd folders omit an end marker: the writer
flushes the range coder after the last input byte, and the reader uses the
folder's declared unpacked size, then requires a zero final range code and
exact packed-input consumption.
`header_compression` optionally stores the ordinary Next Header as a separate
Copy/Deflate/Bzip2/LZMA/LZMA2/PPMd7 stream followed by a `kEncodedHeader`
descriptor.
The encoded-header PackInfo uses the exact offset after all main packed streams;
header filters and recursive header encoding are intentionally disabled.
`bcj2 = true` emits the standard four-packed-stream graph with the selected
compression method on MAIN and independent CALL, JUMP, and range-code streams.
The functionality-first encoder range-codes every marker as “not converted”,
so CALL/JUMP streams can remain empty while preserving fully interoperable BCJ2
wire behavior; moving absolute branch targets into those streams is a later
ratio optimization. `bcj2_start_ip` writes the optional four-byte base property.
BCJ2 and the single-stream classic filters are mutually exclusive. Encrypted
BCJ2 currently requires a zero `bcj2_start_ip`: 7-Zip 26.04 accepts the property
on an unencrypted BCJ2 folder but reports `Unsupported Method` when the same
property is combined with its four-AES mixer graph, so Vort rejects that writer
combination instead of emitting an archive the reference implementation cannot
extract.
`external_names = .copy` (or any other writer compression method) stores the
concatenated UTF-16LE names in a checked `AdditionalStreamsInfo` folder and
writes the FilesInfo name property as external stream index zero. It composes
with solid folders and encoded Next Headers.
`SevenZipParseOptions.max_external_metadata_size` bounds the sum of all decoded
auxiliary folders before any external reference is followed.
Entry creation, access, and modification times are exposed as raw Windows
FILETIME ticks (100 ns intervals since 1601-01-01 UTC), preserving the wire
value without timezone conversion. `attributes` preserves the raw 32-bit 7z
WinAttributes field, including high POSIX mode bits emitted on Unix.
`external_metadata = .copy` (or another writer codec) moves every defined time
and attribute value vector into its own auxiliary folder while leaving the
defined-item bitmap and data-stream index in FilesInfo. Null fields remain
undefined rather than being replaced with synthetic timestamps.

`SevenZipEncodeOptions.encryption` enables AES-256-CBC after the selected
compressor and supplies the UTF-8 password, 16-byte base IV, optional salt, and
KDF cycles power. Passwords are converted to UTF-16LE before the standard 7z
SHA-256 KDF. The default cycles power is 19; power 63 selects the format's
direct-key mode for controlled compatibility tests. Callers must obtain a fresh
unpredictable base IV (and preferably salt) from their own CSPRNG for every
archive. Vort adds each packed-folder sequence number to the IV's low 64 bits,
and reserves four consecutive sequence numbers for an encrypted BCJ2 folder.
Thus MAIN, CALL, JUMP, range-code data, independently packed files, external
metadata, and headers do not reuse an IV inside one archive. The UTF-16LE KDF
and AES-256-CBC block transform are provided by `vail/archive_crypto`; Vort owns
coder properties, IV sequencing, padding, limits, and CRC policy. Supplying the
same IV again for another archive is unsafe.

`encrypt_header = true` requires `encryption` and emits an encoded Next Header
protected by a distinct AES folder. Without it, file names and inline metadata
remain visible even when file data is encrypted. Reader passwords are supplied
through both `SevenZipParseOptions.password` (needed for encrypted headers or
external metadata) and `SevenZipDecodeOptions.password` (needed for file
folders). `max_kdf_cycles_power` rejects hostile KDF settings before hashing.
7zAES is unauthenticated CBC; folder/substream CRCs validate decoded content,
but a wrong password and corrupt ciphertext are not cryptographically
distinguishable.

The current decoder accepts up to six coders. Most folders must be a single
acyclic chain with an optional AES decoder first, a compression coder next, and
only length-preserving Delta/classic BCJ filters after it. AES-only encoded
headers are also accepted. BCJ2 is the explicitly supported branching
exception: exactly one compression coder feeds BCJ2's MAIN input and the other
three inputs map to separate packed streams. It accepts either the two-coder
unencrypted graph or the six-coder graph with one AES coder on each packed
input, deriving semantic MAIN/CALL/JUMP/range mappings from bind pairs rather
than assuming coder order. Other branching or
multi-packed-stream graphs and alternative coder methods are
reported as unsupported instead of being guessed. Additional streams can use
the same supported folder decoders; external folder definitions, names, times,
and attributes are consumed strictly. The writer emits an uncompressed Next
Header and selects one folder per non-empty file by default or one shared folder
when `solid` is enabled. Its LZMA2 mode range-codes greedy new-distance and
repeat matches plus context literals when profitable, otherwise emitting
uncompressed chunks; `lzma2-stored` remains available from the CLI for format
testing. Deeper parsing and cross-chunk dictionary reuse remain future ratio
work. Time and attribute output remains deterministic because the writer emits
only values explicitly supplied by the caller. The differential verifies
Copy/Deflate/Bzip2/LZMA/LZMA2/PPMd7 solid output and all seven encoded-header
modes with the system 7-Zip implementation.
Reader coverage additionally includes independent and solid PPMd7 archives at
orders 2, 6, and 16, PPMd7 composed with Delta/x86 and AES, plus malformed
initialization, truncation, corruption, exact range completion, and
model-memory limit tests.
The reader differential also covers LZMA/LZMA2 BCJ2, including a solid folder
and the reference four-AES graph;
BCJ2 stream lengths, range initialization, packed indices, and output limits
are checked strictly. The writer differential covers all seven main compression
methods plus branch-heavy data, a non-zero unencrypted start IP, encrypted BCJ2,
and all seven external-name and external-metadata compression methods combined
with an encoded header using system 7-Zip. Fixed-mtime system archives verify
reference-reader FILETIME and attribute handling. AES coverage includes all
seven Vort compression methods, encrypted headers, encrypted external metadata,
classic-filter and BCJ2 composition, wrong/missing passwords, and system 7-Zip
archives using its default KDF.
ARM64 and RISC-V branch-heavy inputs are checked in both directions with 7-Zip
26.04; pinned 21.07 fixtures remain for regression coverage of older output.
The source-backed differential covers plain multi-file archives, solid encoded
headers, encrypted encoded headers, encrypted external metadata, and BCJ2 with
four AES branches through real positional file reads. Tests also enforce short
read completion, unrelated-folder skipping, Next Header/packed-stream limits,
source failures, and allocation cleanup.
The symbol-progressive differential adds twelve file-backed cases spanning
Copy, Deflate, Bzip2, LZMA, compressed/stored LZMA2, solid streams, encoded and
encrypted headers, AES data, and x86 filtering. Raw LZMA2 and filter kernels are
also compared against their one-shot implementations across tiny input/output
splits and exhaustive allocation-failure injection.
