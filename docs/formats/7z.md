# 7z archive support

Vort provides a pure Zig reader for common 7z archives and a deterministic
Copy-method writer. The reader supports Copy, Deflate, Bzip2, LZMA, and LZMA2
folders, including compressed Next Headers and solid archives whose files
share one decoded folder stream.

The parser validates the 32-byte signature header and both CRC-32 fields,
7z variable-length integers, packed-stream bounds, folder and substream sizes,
folder/substream CRCs, UTF-16LE filenames, empty files, and directories.
Caller-selected limits bound encoded-header size, dictionary size, selected
entry size, and the complete decoded solid folder.

```zig
const archive = try vort.parseSevenZipArchiveAlloc(allocator, bytes);
defer archive.deinit();

const decoded = try archive.extractByNameAllocLimited(
    allocator,
    "folder/data.bin",
    64 * 1024 * 1024,
);
defer allocator.free(decoded);

const entries = [_]vort.SevenZipEncodeEntry{
    .{ .name = "folder", .kind = .directory },
    .{ .name = "folder/data.bin", .data = payload },
};
const encoded = try vort.encodeSevenZipStoredAlloc(allocator, &entries, .{});
defer allocator.free(encoded);
```

CLI validation surfaces:

```sh
zig build run -- create-7z-file archive.7z payload.bin input.bin
zig build run -- list-7z-file archive.7z
zig build run -- extract-7z-file archive.7z payload.bin output.bin 67108864
zig build run-seven-zip-diff
```

The current decoder accepts one-input/one-output Copy, Deflate, Bzip2, LZMA,
or LZMA2 coders, with one packed stream per folder. Multi-coder BCJ/Delta
chains, BCJ2, encryption, external metadata streams, and alternative coder
methods are reported as unsupported instead of being guessed. The writer emits
an uncompressed Next Header and one independently extractable Copy folder per
non-empty file; timestamps and platform attributes are intentionally omitted
for reproducibility.
