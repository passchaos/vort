# LZMS

Vort provides dependency-free pure Zig encoding and decoding for raw Microsoft
LZMS blocks. The caller supplies the exact decoded size when decoding because
raw LZMS has no container header or end marker.

The decoder implements both logical streams that share an LZMS block:

- forward little-endian 16-bit coding units feeding the adaptive binary range
  decoder;
- backward little-endian 16-bit coding units feeding five adaptive canonical
  Huffman alphabets and their verbatim bits;
- explicit and delayed-LRU repeat offsets for ordinary LZ matches;
- explicit and delayed-LRU `(power, raw offset)` pairs for delta matches;
- bytewise overlapping LZ and delta reconstruction;
- mandatory LZMS x86 relative-address postprocessing.

`LzmsDecoder` owns reusable model/table and x86-filter scratch state. The
one-shot helpers build on its caller-output `decodeInto` method and enforce the
format's 1 GiB block ceiling:

```zig
var decoder = try vort.LzmsDecoder.init(allocator);
defer decoder.deinit();
try decoder.decodeInto(encoded, output);

const decoded = try vort.decodeLzmsAllocLimited(
    allocator,
    encoded,
    exact_decoded_size,
    max_output,
);
defer allocator.free(decoded);

const encoded = try vort.encodeLzmsAlloc(allocator, input);
defer allocator.free(encoded);
```

`encodeLzmsAppend` and `encodeLzmsInto` provide the same transactional
caller-owned surfaces; allocation failure and `OutputTooSmall` leave existing
caller output unchanged.

WIM's solid APIs compose the same raw encoder into packed LZMS resources while
leaving image metadata independently addressable. The resource layer chooses
compressed or raw representation per chunk; solid blob lookup entries retain
logical offsets into the decoded concatenation.

The default encoder now emits LZ, delta and literal items, including explicit
and delayed-LRU repeat offsets. Its bounded greedy matcher retains an in-window
anchor and the latest position per fixed hash bucket. Delta signatures include
the stride phase and search all powers 0...7. Matching runs on the mandatory
x86-transformed input. Complete encoded bytes are compared with the retained
literal reference, so the selected raw stream never exceeds that reference.
WIM's normal and solid resource writers automatically use this same encoder,
then retain raw chunks when compression does not beat the original chunk.

`LzmsEncodeOptions` selects `.greedy` or `.literals`, a hash log from 8 through
20, maximum match distance, optional delta matching/power ceiling, live requested
working-memory budget and output limit. The default history is 8 MiB and the
default hash log is 15. Hash storage is independent of total input length; nine
families with two positions per bucket request 2.25 MiB at the default settings.
The whole-buffer encoder additionally owns transformed input and encoded
candidate/reference buffers; the budget includes those allocations plus x86
scratch, while caller-owned input/output and allocator bookkeeping are excluded.
It reports `WorkingMemoryLimitExceeded` separately from backing allocation
failure. `encodeLzmsWithOptionsAlloc`, `encodeLzmsWithOptionsInto`, and
`encodeLzmsWithOptionsAppend` share the same selection. `encodeLzmsLiteralAlloc`
retains the previous deterministic reference bytes. `encodeLzmsWithSummaryAlloc`
returns owned bytes, selected-path/match counts, maximum offsets and peak logical
working bytes; release the result with `deinit(allocator)`.

This is a portable functional greedy encoder, not wimlib-level optimal parsing
or a throughput-parity claim. Adaptive cost estimation is deliberately simple;
final complete-wire arbitration keeps rejected plans outside the public output.

```sh
zig build run -- encode-lzms-file input.bin output.lzms
zig build run -- decode-lzms-file input.lzms output.bin 1048576
zig build test-lzms test-wim
zig build -Doptimize=ReleaseFast run-lzms-match-diff -- \
  --wimlib-dir /path/to/wimlib --report /tmp/lzms-matches.json
zig build run-lzms-diff -- --wimlib-dir /path/to/wimlib
```

The pinned raw fixture is generated by wimlib. The optional differential builds
a small wimlib compression/decompression oracle and checks repetitive text,
delta-friendly byte series, mixed data, project source, and synthetic x86 call
and RIP-relative instruction streams in both directions. wimlib independently
decodes the tested Vort-generated raw blocks, and the repeated case must be smaller
than its source.

Raw LZMS carries no checksum and has no terminal marker, so not every same-size
bit corruption is intrinsically detectable. Containers such as WIM provide the
decoded size and SHA-1 verification; Vort applies both when extracting WIM/ESD
resources.

The matching differential covers 39 input/strategy combinations, 30 successful
independent wimlib raw decodes and ten hand-planned LZ/delta/repeat/large-field
cases. One plan uses 30-bit length and offset fields and restores 106,685,608
bytes. The pinned wimlib cd5e231 decoder faults when its output is one or two
bytes; the C harness explicitly reports this limitation without modifying the
library. Vort's empty/tiny native tests and literal byte equality remain required.
CLI option/limit failures preserve existing output and remove temporary files;
encoding can atomically replace the same pathname used for input.
