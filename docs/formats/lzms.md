# LZMS

Vort provides dependency-free pure Zig encoding and decoding for raw Microsoft
LZMS blocks. The caller supplies the exact decoded size when decoding because
raw LZMS has no container header or end marker.

The decoder implements both logical streams that share an LZMS block:

- forward little-endian 16-bit coding units feeding the adaptive binary range
  decoder;
- backward little-endian 16-bit coding units feeding five adaptive canonical
  Huffman alphabets and their verbatim bits;
- explicit and delayed-LRU repeat offsets for ordinary LZ matches;
- explicit and delayed-LRU `(power, raw offset)` pairs for delta matches;
- bytewise overlapping LZ and delta reconstruction;
- mandatory LZMS x86 relative-address postprocessing.

`LzmsDecoder` owns reusable model/table and x86-filter scratch state. The
one-shot helpers build on its caller-output `decodeInto` method and enforce the
format's 1 GiB block ceiling:

```zig
var decoder = try vort.LzmsDecoder.init(allocator);
defer decoder.deinit();
try decoder.decodeInto(encoded, output);

const decoded = try vort.decodeLzmsAllocLimited(
    allocator,
    encoded,
    exact_decoded_size,
    max_output,
);
defer allocator.free(decoded);

const encoded = try vort.encodeLzmsAlloc(allocator, input);
defer allocator.free(encoded);
```

`encodeLzmsAppend` and `encodeLzmsInto` provide the same transactional
caller-owned surfaces; allocation failure and `OutputTooSmall` leave existing
caller output unchanged.

The deterministic reference encoder writes literal items through the real
forward adaptive range stream and backward adaptive canonical-Huffman stream,
including mandatory x86 preprocessing. Adaptive literal coding already
compresses skewed text and byte distributions; ordinary LZ matches, delta
matches and their recent-offset queues remain ratio/performance work. WIM
composition compares each encoded chunk with its input and retains raw bytes
when this reference representation is not smaller.

```sh
zig build run -- encode-lzms-file input.bin output.lzms
zig build run -- decode-lzms-file input.lzms output.bin 1048576
zig build test-lzms
zig build run-lzms-diff -- --wimlib-dir /path/to/wimlib
```

The pinned raw fixture is generated by wimlib. The optional differential builds
a small wimlib compression/decompression oracle and checks repetitive text,
delta-friendly byte series, mixed data, project source, and synthetic x86 call
and RIP-relative instruction streams in both directions. wimlib independently
decodes every Vort-generated raw block, and the repeated case must be smaller
than its source.

Raw LZMS carries no checksum and has no terminal marker, so not every same-size
bit corruption is intrinsically detectable. Containers such as WIM provide the
decoded size and SHA-1 verification; Vort applies both when extracting WIM/ESD
resources.
