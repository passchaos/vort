# Zstd one-shot decode vs libzstd, 2026-11-09

## Protocol

- Zig 0.16.0 `ReleaseFast`, `x86_64-linux-gnu`, `skylake+pku+sgx`; Intel Core
  i7-10700K; logical CPU 15 pinned with `taskset`.
- Reference frames are generated by system libzstd 1.4.8 at levels 3 and 19.
  Vort uses one-shot `decodeFrameInto`; the reference uses `ZSTD_decompress`.
- Twelve Silesia sources at 64 KiB and 1 MiB prefixes; three alternating
  rounds; 500 iterations for 64 KiB and 100 for 1 MiB; per-row medians.
- Binary SHA-256
  `ac25d33c6ca25e77358d10ccfd0087a9e941d5cf776b8cb2e6f37269d1915bac`.
- Raw rows: [matrix.csv](data/zstd-decode-current-20261109/matrix.csv).
- Reproduce with `zig build run-zstd-reference-bench -- --input FILE
  --name NAME --level LEVEL --iterations N`.

## Result

`reference_over_vort_time` is reference time divided by Vort time; values
below one mean Vort is slower.

| 3 | 1 MiB | 0.7220 | 1.38x |
| 19 | 64 KiB | 0.6709 | 1.49x |
| 19 | 1 MiB | 0.6923 | 1.44x |
| all 48 rows | | **0.7067** | **1.42x** |

Strongest row: `x-ray.64k` level 3 at `0.9356` (1.07x slower). The current
head includes the 2026-11-09 dense split policy
(`wide_copy_sequence_min = 1024`), which improved `nci`/`xml` 64 KiB level 3
by about 33%; the remaining weak rows are mostly level 19, where different
block shapes and per-block setup dominate.

## Next
