# Incremental Deflate compact table preparation

Dynamic blocks handled by the caller-owned semantic workspace no longer build
the compact literal and distance primary lookups. Compact admission and
transactional semantic fallback expand those lookups from the canonical
Huffman entries already retained for long-code misses. This avoids counting
lengths and reversing the same codes twice. Alphabet validation and tree
construction remain mandatory before either path runs.

`prepareDynamicTables` keeps once-per-block validation, tree construction and
semantic admission outside the symbol-heavy `step` body. Compact Huffman
helpers and semantic-window tests now live in cohesive submodules. Caller
history, workspace ownership, output limits and public progress semantics
remain as before.

## Measurement

Baseline codec source: `0572c832`. Both binaries use the same guarded public
raw-incremental harness, Zig 0.16.0 ReleaseFast,
`x86_64-linux-gnu -mcpu=skylake+pku+sgx`, logical CPU2 on an Intel Core
i7-10700K. Each process performs one warmup and 64 timed calls, with a fresh
decoder and caller workspace per call. File reads, allocations, complete
output comparisons and SHA/guard verification are outside the timed interval.
Decoding itself runs on one thread with 64 KiB caller history and 4 KiB output
slices.

The twelve Silesia sources use their first 64 KiB and 1 MiB, raw Deflate
levels 6 and 9, generated by zlib 1.2.11 with window bits -15, memory level 8,
default strategy and `Z_FINISH`. Five alternating baseline/candidate sweeps
cover 96 rows and 960 processes. Every process verifies complete content,
exact input/output sizes, SHA-256 and output guards. Ratios below are geometric
means of each row's median paired candidate/baseline latency ratio; smaller is
better.

| Scope | Level | Whole compressed input | 4 KiB input slices |
| --- | ---: | ---: | ---: |
| 64 KiB | 6 | 0.95707 | 0.98856 |
| 64 KiB | 9 | 0.95463 | 0.99026 |
| 1 MiB | 6 | 0.96283 | 0.99650 |
| 1 MiB | 9 | 0.96521 | 0.99636 |

Whole-input latency improves 3.5–4.5%; every whole-input row median improves.
Fragmented-input group means improve 0.4–1.1%, with a maximum individual row
ratio of 1.00715. The small fragmented gains do not establish a broad speed
claim beyond this matrix. [Per-row CSV](compact-tables-20261102.csv) preserves
all medians and paired win counts.

## Reproduction and validation

From the repository root, generate the corpus and archive the baseline:

```sh
python3 tools/deflate/incremental_decode_corpus.py \
  --source-dir /home/passchaos/Work/corpora/silesia-20261025/files \
  --output-dir zig-out/deflate-lazy-20261102/corpus
mkdir -p zig-out/deflate-lazy-20261102/baseline-source
git archive 0572c832 src | tar -x -C zig-out/deflate-lazy-20261102/baseline-source
```

Compile the same harness against each source snapshot:

```sh
zig build-exe -OReleaseFast -target x86_64-linux-gnu -mcpu=skylake+pku+sgx \
  --dep deflate -Mroot=bench/deflate/raw_incremental_decode.zig \
  -Mdeflate=zig-out/deflate-lazy-20261102/baseline-source/src/deflate.zig \
  -femit-bin=zig-out/deflate-lazy-20261102/baseline
zig build-exe -OReleaseFast -target x86_64-linux-gnu -mcpu=skylake+pku+sgx \
  --dep deflate -Mroot=bench/deflate/raw_incremental_decode.zig \
  -Mdeflate=src/deflate.zig -femit-bin=zig-out/deflate-lazy-20261102/cold-prepare
python3 tools/deflate/incremental_decode_compare.py \
  --manifest zig-out/deflate-lazy-20261102/corpus/manifest.json \
  --baseline zig-out/deflate-lazy-20261102/baseline \
  --candidate zig-out/deflate-lazy-20261102/cold-prepare \
  --output zig-out/deflate-lazy-20261102/cold-report.json \
  --cpu 2 --sweeps 5 --iterations 64
```

The generator additionally records source hashes and validates its reference
round trips. Re-generation produced identical hashes for all 48 input/wire
bindings. Absolute manifest paths and generator metadata affect the manifest
hash; the comparison validates the individual payload bindings independently.

The final focused suite passes 590/590 tests in ReleaseSafe. New reference
tests compare all primary entries against the original length-based builder
at 7/10/11 lookup bits and 19/30/32/286 symbol capacities, including singleton
trees, 15-bit tails, absent symbols and poisoned table reuse. Window tests
prove compact tables stay untouched for semantic blocks, are rebuilt from the
current alphabet after fallback, and preserve output/progress through three
changing dynamic alphabets, backpressure and reset. The fresh incremental gzip
gate also passes against runtime zlib 1.2.11.

Earlier layouts retained a 1–2% fragmented-input regression. Preserving the
old preparation order did not resolve it, and outlining the symbol loop
regressed 5.2% on a twelve-source 1 MiB level-9 screen. Those variants were
discarded. The retained change outlines only the once-per-block table work.
Wider semantic admission and direct caller-output decoding remain open.
