# Reference decoder implementation study, 2026-11-12

This study translates checked local reference implementations into candidate
Vort mechanisms. It is source evidence, not a new performance result. The
current full matrix remains the separate [21e4a1d0 refresh](modern-decode-refresh-20261112.md).

## Deflate mechanisms and next targets

libdeflate's [copy template](https://github.com/ebiggers/libdeflate/blob/92e6a0db9fa848d742f9eb286c92afc60f2c3dda/lib/decompress_template.h#L590)
limits live copy values through sequential small load/store groups. For
distance at least the machine word size, the next load may use output just
generated by the preceding store. Its fast path proves output slack separately
from logical advancement; the [bounded tail](https://github.com/ebiggers/libdeflate/blob/92e6a0db9fa848d742f9eb286c92afc60f2c3dda/lib/decompress_template.h#L707)
checks actual length/history before exact byte replay.

Vort's exact non-overlap copy can use immediate fixed-block stores without
holding two large aggregate arrays live. This is the rationale for the
interleaved copy candidates. The reference's distance2..7 wild loads are not
a valid Vort initialized-source proof: they can touch speculative suffix
bytes. Exact physical capacity, window pause, reader progress and caller
scratch behavior remain independent gates.

The next larger preparation target is a checked lengths-to-semantic plan:
validate canonical enumeration once, fill semantic primary/secondary entries
and invalid sentinels directly, and construct a general canonical fallback
only when the semantic shape is unsupported. Vort's owner/dense preparation
screens improved only about 0.5%/1.6%; removing a small extra scan is insufficient.
The bounded tail must consume the same validated plan. Scalar/canonical
implementations remain oracles, and every incomplete tree currently accepted
must retain its valid codes and exact missing-code errors.

libdeflate's [table layout](https://github.com/ebiggers/libdeflate/blob/92e6a0db9fa848d742f9eb286c92afc60f2c3dda/lib/deflate_decompress.c#L335)
uses fixed distance8 and up-to-litlen11 lookup widths, direct semantic entries
and progressive table doubling. Vort already uses relevant doubling and low-
width techniques. The reference rejects incomplete shapes that Vort accepts;
its empty/singleton completion must not replace Vort's canonical-zero and
invalid-hole contracts. Whole-decoder CPU selection occurs outside the symbol
loop; both current Skylake comparisons already use BMI2-capable builds.

## Zstd mechanisms and next targets

The first priority is an installed HUF execution plan. Upstream
[HUF DTable construction](https://github.com/facebook/zstd/blob/01b7154f1172432f8abe9b3bb9909e14a1176b7d/lib/decompress/huf_decompress.c#L388)
fills the final table from weights/ranks and DCtx retains it. Vort's small
seven-bit path already has direct lookup construction. The remaining general
X1/X2 paths rebuild lookup tables, while treeless retains only the tree.
Install generation-owned X1 and derive X2 only when selected by block shape;
the entropy workspace's 64 KiB cap forbids unconditional wide-X2 residency.
Dictionary initialization, missing treeless predecessors, exact stream ends
and cross-call frame reset remain explicit contracts.

Second, unify sequence modes through stable owner/view state. Upstream
[sequence setup](https://github.com/facebook/zstd/blob/01b7154f1172432f8abe9b3bb9909e14a1176b7d/lib/decompress/zstd_decompress_block.c#L647)
selects static predefined tables, one-entry RLE, owned compressed tables or
the previous table pointer. Vort's cursor already borrows Spec; remaining
full-table assignments and repeat resolution are the new ownership target.
Cache eviction, staging/commit and failed predecessor/reps state must be
defined before an executor borrows a view. RLE oracle states cannot become an
unchecked entries[state] indexing rule.

Third, remove the 128 KiB literal stack scratch where the passed output slice
provides a proved safe empty region after current-block maximum output.
Upstream uses output slack for this purpose; Vort must respect its cropped
frame-output slice and literal collision/overcopy bounds. Otherwise use an
explicit retained bounded scratch. This addresses stack and checks, not a
claim that HUF literals or most literal copies disappear.

## Brotli mechanisms and next targets

The first priority is replacing canonical→packed→expand with directly executable
bounded Huffman table groups. Upstream
[group construction](https://github.com/google/brotli/blob/558fc647cdaf391228d614ca85f711e02e4e583b/c/dec/decode.c#L1022)
and [two-level table fill](https://github.com/google/brotli/blob/558fc647cdaf391228d614ca85f711e02e4e583b/c/dec/huffman.c#L169)
retain each tree's final slots for the meta-block. Vort's packed command/distance
single slots can repeatedly expand trees after switches. Replace the old
representation, use actual slot counts under an explicit budget and route
cold long codes through checked secondary tables. Adding another 512 KiB
lookup plane repeats an already rejected mechanism. Upstream per-meta-block
allocation/free is not the desired Vort retained-workspace lifecycle.

Second, prove input slack at command/literal phases and use an internal reader
whose fast operations consume that proof, exiting to exact tails. Upstream
[reader guard](https://github.com/google/brotli/blob/558fc647cdaf391228d614ca85f711e02e4e583b/c/dec/bit_reader.h#L21)
derives its 28-byte slack from its own maximum phase consumption. Vort must
derive a separate bound including block switches, long runs and partial
logical bit lengths; copying the constant or merely moving a limits branch
does not implement this contract.

Third, consider local rotating recent-distance history inside wide10 generic,
materializing the existing [4] state at success and error boundaries. Upstream
[history update](https://github.com/google/brotli/blob/558fc647cdaf391228d614ca85f711e02e4e583b/c/dec/decode.c#L2333)
writes one slot, while Vort shifts three values. New index/register costs may
offset fewer writes. Implicit/short-distance rules and static dictionary
non-updates cannot change. This small candidate alone is not a Mozilla q11
cliff-repair plan.

## Acceptance and priority

Every candidate needs current-source whole-operation cold and matched-reuse
comparisons, competitor revision/API/CPU provenance, raw samples and paired
statistics. Wire/output/error/progress/guard and explicit memory limits are
hard gates; exact-output optimization requires at least 3% gain with control
rows at least0.98x, and a declared cliff repair requires20% target gain.
Do not repeat pointer-cache, aggregate-layout or mode-only negative screens
without a new invariant. The highest-ROI structural frontier is final execution
table lifetime and eliminating full intermediate materialization, especially
Brotli wide10 generic and general Zstd HUF/sequence state.
