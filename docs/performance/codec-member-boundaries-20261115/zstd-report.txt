Root cause: src/zstd.zig:8042 fulfilledPledgeStartsDataMember uses first data-magic byte to reject a new frame once expected_output_len is fulfilled. This misclassifies zero-output frames and reads items[0] without an empty-buffer guard.

1. Empty input poll: prevalidated_frame + expected_output_len=0 + step(empty,empty) aborts at zstd.zig:8047 (index 0, len 0), called at :7328/:7231.
2. Valid empty frame 28b52ffd2000010000: whole input succeeds (done/read9); first-byte input fails (SizeMismatch/read1). block_stream succeeds both ways. libzstd 1.4.8 decodes zero bytes.
3. Nonempty FCS=1 frame 28b52ffd200109000061 at pledge0/output capacity0: prevalidated_frame returns need_output/read10 and finish OutputTooSmall. block_stream correctly returns SizeMismatch at admitted header/read6.
4. Truncated empty checksum frame 28b52ffd240001000099e9d8: old prevalidated_frame reports SizeMismatch/read12; block_stream reports need_input then finish TruncatedFrame.
5. Full empty frame with invalid checksum: both policies report ChecksumMismatch.

Fix boundary: remove the magic-only heuristic. A complete admitted header may reject FCS > remaining pledge, after dictionary admission and with existing output-limit precedence. Unknown FCS must wait for block/frame preflight, because compressed blocks can regenerate zero bytes. Complete zero-byte frames still validate checksum and exact footer length.
