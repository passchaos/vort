# Zstd small-copy sequence policy, 2026-11-09

## Change

`sequence_decode_policy.wide_copy_sequence_min` moves from 2048 to 1024.
Blocks with the `preferSmall` shape (`literal_bytes <= 4096` and
`sequence_count <= 4096`) whose sequence count is in `[1024, 2048)` now use
the dense four-stream split executor instead of the compact small-copy split
executor. The dense path is selected because this shape also has
`regenerated_size <= 16 KiB`. No wire bytes, frame parameters or encoder
behavior change; only the decoder executor choice changes.

- Zig 0.16.0 `ReleaseFast`, `x86_64-linux-gnu`, `skylake+pku+sgx`; Intel Core

- Reference frames are generated by system libzstd 1.4.8 through
  `tools/zstd/reference_bench.zig`; the timed API is one-shot

- Alternating base/candidate processes; ratios are candidate/base paired by

## 1 MiB matrix

The 24-row geometric mean is `0.997312`; every row is between `0.9628` and
`1.0039`. Only `xml` improves materially (`0.9628` at level 3, `0.9747` at
level 19). Other sources are neutral within the measured process noise.

## Aggregate and conclusion

Across the 36-row combined matrix the geometric mean is `0.968166`, the
target weak rows improve by at least 26%, and the worst control is `1.0039`
(above the `0.98x` non-regression floor). The earlier three-round 48-row
screen was noise-dominated: unchanged rows varied by up to about 4% between
processes, while the nine-round paired focus centers them at parity. Adopt
the 1024 threshold.

Decoder differential tests, the focused Zstd suite and the source-backed
decode gates remain the correctness controls; no compressed-size change is
expected or observed.
