# Puffin empty distance and checked dynamic metadata candidate

All changes are confined to this temporary copy. The main repository's 2093
source files were rehashed and confirmed unchanged. No main build, source edit
or commit was performed.

Public root API before evidence:
- puffAndroidDeflatePaddedAlloc rejects the legal sample14 original with
  InvalidPuffinStream because its DISTS=[0] alphabet has max_bits=0.
- huffAndroidDeflateAlloc independently rejects an equivalent Puffin stream
  generated by a separate Python bit/canonical-code parser.
- HLIT raw31 / HDIST raw31 with repeats 138+138+44 panics at index320/len316
  through the public puffer; before-counts.exit-code records SIGABRT as -6.

Final public after evidence:
- puffer produces exactly 218 independently expected Puffin bytes, exact991 bits.
- huffer restores the original 124 raw bytes bit exactly.
- malformed field counts return InvalidPuffinStream without panic.

Production change in src/android_ota/puffin_codec.zig:
- Huffman.initDistance alone allows a max_bits=0 error-marker table.
  Actual distance encode/decode still fails InvalidPuffinStream.
  Empty CODES and LENS retain their previous rejection.
- DynamicCounts shares the supported HLIT/HDIST/HCLEN bounds (286/30/19) and
  total316 limit between puffer and huffer. Literal and repeat spans use checked
  subtraction-based vector bounds before indexing.
- Public huff expected-bit rounding uses checked addition and returns
  IntegerOverflow for overflowing total_bits+7.
- PuffReader validates encoded distance below 32768 before u16+1, rejecting
  0x8000/0xffff safely; truncated distance retains InvalidPuffinStream.

This is metadata/token conversion, not ordinary Deflate inflation.
No ordinary tree completeness, singleton-width or history validity checks were
added. Positive controls preserve incomplete CODES/LENS/DIST, singleton EOB
width7, and match-first tokens that are representable by Puffin.

Focused tests are split under src/android_ota/puffin_codec_tests/:
- original real sample, independent expected Puffin and exact bits.
- bidirectional equality of metadata/pcodes and raw bits at all offsets0..7.
- maximum supported counts and vector316.
- unsupported HLIT/HDIST raw30/31, HCLEN16, and checked repeat317>316.
- empty CODES/LENS, actual empty-distance use, invalid/truncated distance token.
- caller input and enclosing canary preservation.
- exact output-cap boundary, OutputLimitExceeded, SizeMismatch, OutputTooSmall,
  IntegerOverflow and per-allocation OutOfMemory cleanup plus retry.

Final validation of the same frozen source:
- native filter Puffin: all14 tests passed, including existing fixed/stored/dynamic.
- x86-linux-musl filter Puffin: all14 tests passed.
- wasm32-wasi filter Puffin: all14 tests passed through the copied Node WASI gate.
- zig fmt --check and git apply --check passed.

AOSP reference source at commit 56246e65146cbf7b736343c95a3e8ed970b9d106 is
retained under reference/aosp with URLs/SHA in aosp-source-provenance.json.
Its InitHuffmanCodes rejects oversubscription but does not require completeness
or one-bit singletons. Puffer/huffer parse and encode tokens without history
checks, and CheckHuffmanArrayLengths restricts 286/30/19. No local AOSP executable
was available, so no binary AOSP interoperability claim is made.
