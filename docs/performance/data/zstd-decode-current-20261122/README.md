# Current-source Zstd decode matrix, 2026-11-22

## Method

- Host Intel i7-10700K, Linux 6.8, Zig 0.16.0 ReleaseFast, single thread;
  system libzstd **1.4.8** as the reference in every row.
- `run-zstd-reference-bench`, `decodeFrameInto` versus `ZSTD_decompress`,
  one-shot, 64 KiB prefixes at 400 iterations and 1 MiB prefixes at 80.
- Wires are generated by libzstd level 9; every row is verified by both
  implementations before timing.

## Result

| Prefix | geometric Vort/reference | weakest rows |
| --- | ---: | --- |
| 64 KiB | **0.7774x** | xml 0.6799, nci 0.6894, reymont 0.7270, samba 0.7375 |
| 1 MiB | **0.7805x** | reymont 0.7177, webster 0.7278, dickens 0.7380, mozilla 0.7410 |
| all 24 | **0.7789x** | |

`x-ray.64k` 0.9944x and `sao.1m` 0.8754x are the strongest rows. The weak
rows are text-like command-dense inputs, matching the profile in
[decode-optimization-status.md](../../decode-optimization-status.md): the dense
sequence decoder is 64.1% of the run and its hottest instruction is the
16-byte match load/store. Local copy reorders and wider wildcopy tiers are
already closed, so the remaining gap needs a fused state machine or a
different table/token layout.
