# Brotli one-shot decode vs libbrotli, 2026-11-09

First current-source Brotli decode matrix. The 2026-11-01/02
[decode status](decode-optimization-status.md) table reports Brotli 6/11 at
1.22x full-file and 1.48x at 64 KiB; those epochs predate the current decoder
and must not be read as current-head rankings.

## Protocol

- Zig 0.16.0 `ReleaseFast`, `x86_64-linux-gnu`, `skylake+pku+sgx`; Intel Core
  i7-10700K; logical CPU 15 pinned with `taskset`.
- Frames are generated by system libbrotli 1.0.9 at qualities 6 and 11.
- Vort uses one-shot `brDecodeStreamInto`; the reference uses
  `BrotliDecoderDecompress` from the same libbrotli.
- Twelve Silesia sources at 64 KiB and 1 MiB prefixes; two invocations per row
  with 500/100 iterations; per-row medians. Each invocation alternates the two
  implementations over five rounds and keeps the best sample per codec.
- Reproduce with `zig build run-br-reference-bench -- --input FILE --name NAME
  --quality Q --iterations N`.

## Result

`reference_over_vort_time` is libbrotli time divided by Vort time; values below
one mean Vort is slower.

| Quality | Prefix | Geometric ref/Vort | Vort slower |
| --- | --- | ---: | ---: |
| 6 | 64 KiB | 0.5989 | 1.67x |
| 6 | 1 MiB | 0.8067 | 1.24x |
| 11 | 64 KiB | 0.6602 | 1.51x |
| 11 | 1 MiB | 0.8213 | 1.22x |
| all 48 rows | | **0.7154** | **1.40x** |

Weakest rows: `nci.64k` q6 0.3435, `xml.64k` q6 0.3633, `nci.64k` q11 0.4169,
`xml.64k` q11 0.4430, `mr.64k` q6 0.4524, `mozilla.64k` q6 0.4917.

Strongest rows: `sao.1m` q6 1.0329 and `mozilla.1m` q11 1.0126 (Vort faster than
libbrotli), `sao.1m` q11 0.9585.

Profiles of `nci.64k` q6 put 25.5% of Vort decode time in
`processMinimalCompressedMetaBlock`, 9.7% in `readCommandSymbol`, 9.0% in
`readMinimalDistance`, 8.2% in `peekBitsPadded`, 6.5% in `readBits`, 7.4% in the
command Huffman lookup, and about 12% in literal/command prefix decodes. The
64 KiB command-dense rows pay per-symbol helper call overhead that libbrotli
avoids in its fused state machine.

## Increment: inline per-symbol tree lookups

`readCommandSymbol`, `commandPrefixForDecode`, `literalPrefixForDecode`, and
`distancePrefixForDecode` are now `inline`. A 48-row paired A/B with
`--vort-only` (3 alternating rounds, same 500/100 iterations) measures:

| Group | new/old time geomean |
| --- | ---: |
| q6, 64 KiB | 0.9901 (-0.99%) |
| q6, 1 MiB | 0.9987 (-0.13%) |
| q11, 64 KiB | 0.9882 (-1.18%) |
| q11, 1 MiB | 1.0026 (+0.26%) |
| all 48 rows | **0.9949 (-0.51%)** |

Bootstrap 95% interval over rows: `[-0.98%, -0.09%]`. The weak 64 KiB rows move
most: `mr.64k` q6 -4.95%, `nci.64k` q11 -4.01%, `mr.64k` q11 -3.87%,
`mozilla.64k` q6 -3.81%, `xml.64k` q6 -3.19%, `nci.64k` q6 -3.19%.

Two large rows regress about 2%; an 8-round recheck confirms `nci.1m` q6 +1.75%
and `reymont.1m` q11 +1.96%, while `osdb.64k` q6 is +0.83%. A bisect shows the
regressions come from inlining the three tree lookups (the 64 KiB gains do too);
inlining only `readCommandSymbol` is neutral on all four probed rows. The 1 MiB
group geometric means remain neutral because other large rows improve.

This increment is below the default 3% geometric-mean bar; it is kept as a
target-row improvement for the command-dense 64 KiB rows, with every verified
control above the 0.98x floor.

## Increment: cache resolved tree pointers per block type

The generic prepared-lookup payload re-resolved every tree on each symbol:
the command tree through an index check plus packed-tier comparison, and
literal/distance trees through the context map plus bounds check. The
prepared paths now pin resolved pointers for the current command block type
and, for frames that stay inside the inline tiers, the 64 literal-context
trees and four distance-context trees. Block switches re-resolve only the
affected set. Frames with more than 64 literal or 64 distance trees keep the
per-symbol expansion path: an ungated experiment pinned mostly-null optional
pointers for those frames and regressed `x-ray.1m` q11 about 2%.

`readCommandSymbol` and `commandPrefixForDecode` revert to regular calls;
the literal/distance lookup helpers stay inline for the packed-tier fallback.
The cached payload owns the hot resolution itself.

A five-round 48-row paired `--vort-only` A/B against the inline increment
measures:

| Group | new/old time geomean |
| --- | ---: |
| q6, 64 KiB | 0.9838 (-1.62%) |
| q6, 1 MiB | 0.9994 (-0.06%) |
| q11, 64 KiB | 0.9876 (-1.24%) |
| q11, 1 MiB | 0.9955 (-0.45%) |
| all 48 rows | **0.9916 (-0.84%)** |

Bootstrap 95% interval over rows: `[-1.27%, -0.45%]`. The command-dense
64 KiB rows carry the gain: `mr.64k` q6 -5.04%, q11 -4.72%; `nci.64k` q6
-4.46%; `xml.64k` q6 -3.68%; `mozilla.64k` q6 -3.08%, q11 -3.46%. Worst
controls are `dickens.1m` q6 +0.98% and `reymont.1m` q6 +0.97%; every row
stays above the 0.98x floor. The ungated variant measured 0.9908 overall but
`x-ray.1m` q11 +2.12% in an eight-round recheck; the inline-tier gate
restores that row to +0.05%.

## Increment: select prepared kernels by decoded meta-block length

Kernel selection for the wider prepared/tail-lookup payloads was keyed on
compressed stream size (`large_stream_decode_threshold`, 16 KiB of wire).
Highly compressible 64 KiB inputs produce only a few kilobytes of wire
(`nci.64k` q6 is 4,214 bytes), so they stayed on the generic prepared-lookup
loop and never reached the flat/external literal-lookup kernels, despite
having a 64 KiB decoded meta block. The one-shot minimal path now shares the
large-frame dispatch, keyed on decoded meta-block length and tree shape;
frames with a caller shared dictionary and meta blocks below 64 KiB keep the
generic loop. The shared dispatcher is `inline`; an out-of-line first cut
regressed `nci.1m` about +2.3% from the extra per-frame call.

A five-round 48-row paired `--vort-only` A/B against the tree-pointer
increment measures:

| Group | new/old time geomean |
| --- | ---: |
| q6, 64 KiB | 0.8895 (-11.05%) |
| q6, 1 MiB | 0.9988 (-0.12%) |
| q11, 64 KiB | 0.9272 (-7.28%) |
| q11, 1 MiB | 1.0038 (+0.38%) |
| all 48 rows | **0.9536 (-4.64%)** |

Bootstrap 95% interval over rows: `[-7.80%, -1.77%]`. The command-dense
64 KiB cliff is repaired far past the weak-row bar: `mozilla.64k` q6
-31.82%, `mr.64k` q6 -30.55%, `xml.64k` q6 -29.07%, `nci.64k` q6 -27.93%,
q11 rows -15.84% to -23.79%. Worst control is `xml.1m` q11 +1.94%; every
row stays above the 0.98x floor. An earlier out-of-line dispatch measured
the same 64 KiB wins but regressed `nci.1m` +2.3%; inlining the dispatcher
returns that row to -1.53%/+0.06% in eight-round rechecks.

Raw rows: [inline five-round A/B](data/brotli-decoded-size-dispatch-20261109/decoded-size-dispatch-inline-5r.csv)
and the rejected [out-of-line first cut](data/brotli-decoded-size-dispatch-20261109/decoded-size-dispatch-5r.csv).

medians) after the inline, tree-pointer, and decoded-size-dispatch
increments:

| Quality | Prefix | Geometric ref/Vort | Vort slower |
| --- | --- | ---: | ---: |
| 6 | 64 KiB | 0.6888 | 1.45x |
| 6 | 1 MiB | 0.8082 | 1.24x |

| 11 | 1 MiB | 0.8197 | 1.22x |
| all 48 rows | | **0.7594** | **1.32x** |

The full-matrix ratio moves from 0.7154 to 0.7594 (+6.1% relative
throughput). The command-dense 64 KiB rows improve most: `nci.64k` q6 from
0.3435 to about 0.52, `xml.64k` q6 from 0.3633 to about 0.55; `sao.1m` q6

rows: [matrix-post-dispatch.csv](data/brotli-decode-current-20261109/matrix-post-dispatch.csv).

## Rejected: ten-bit fused external command lookup in the 10-bit literal path

Wiring the prepared 10-bit fused command lookup (`readInsertCopyLengthsExternalLookup10Current`)
into the auxiliary `processExternalLiteralLookupCompressedPayload`, with
in-table nine-bit distance tail lookups, built and stayed correct only when
distances kept the existing tail9 helper; the external-distance variant
failed `InvalidHuffmanCode` on the command-dense rows. The correct
command-10-only variant measured a 48-row three-round A/B geomean of
`1.0075` (+0.75%, q11 1 MiB +1.50%) with no target-row benefit, so it was
reverted. Do not retry without a different distance-lookup integration.
