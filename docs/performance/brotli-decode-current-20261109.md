# Brotli one-shot decode vs libbrotli, 2026-11-09

First current-source Brotli decode matrix. The 2026-11-01/02
[decode status](decode-optimization-status.md) table reports Brotli 6/11 at
1.22x full-file and 1.48x at 64 KiB; those epochs predate the current decoder
and must not be read as current-head rankings.

## Protocol

- Zig 0.16.0 `ReleaseFast`, `x86_64-linux-gnu`, `skylake+pku+sgx`; Intel Core
  i7-10700K; logical CPU 15 pinned with `taskset`.
- Frames are generated by system libbrotli 1.0.9 at qualities 6 and 11.
- Vort uses one-shot `brDecodeStreamInto`; the reference uses
  `BrotliDecoderDecompress` from the same libbrotli.
- Twelve Silesia sources at 64 KiB and 1 MiB prefixes; two invocations per row
  with 500/100 iterations; per-row medians. Each invocation alternates the two
  implementations over five rounds and keeps the best sample per codec.
- Reproduce with `zig build run-br-reference-bench -- --input FILE --name NAME
  --quality Q --iterations N`.

## Result

`reference_over_vort_time` is libbrotli time divided by Vort time; values below
one mean Vort is slower.

| Quality | Prefix | Geometric ref/Vort | Vort slower |
| --- | --- | ---: | ---: |
| 6 | 64 KiB | 0.5989 | 1.67x |
| 6 | 1 MiB | 0.8067 | 1.24x |
| 11 | 64 KiB | 0.6602 | 1.51x |
| 11 | 1 MiB | 0.8213 | 1.22x |
| all 48 rows | | **0.7154** | **1.40x** |

Weakest rows: `nci.64k` q6 0.3435, `xml.64k` q6 0.3633, `nci.64k` q11 0.4169,
`xml.64k` q11 0.4430, `mr.64k` q6 0.4524, `mozilla.64k` q6 0.4917.

Strongest rows: `sao.1m` q6 1.0329 and `mozilla.1m` q11 1.0126 (Vort faster than
libbrotli), `sao.1m` q11 0.9585.

Profiles of `nci.64k` q6 put 25.5% of Vort decode time in
`processMinimalCompressedMetaBlock`, 9.7% in `readCommandSymbol`, 9.0% in
`readMinimalDistance`, 8.2% in `peekBitsPadded`, 6.5% in `readBits`, 7.4% in the
command Huffman lookup, and about 12% in literal/command prefix decodes. The
64 KiB command-dense rows pay per-symbol helper call overhead that libbrotli
avoids in its fused state machine.

## Increment: inline per-symbol tree lookups

`readCommandSymbol`, `commandPrefixForDecode`, `literalPrefixForDecode`, and
`distancePrefixForDecode` are now `inline`. A 48-row paired A/B with
`--vort-only` (3 alternating rounds, same 500/100 iterations) measures:

| Group | new/old time geomean |
| --- | ---: |
| q6, 64 KiB | 0.9901 (-0.99%) |
| q6, 1 MiB | 0.9987 (-0.13%) |
| q11, 64 KiB | 0.9882 (-1.18%) |
| q11, 1 MiB | 1.0026 (+0.26%) |
| all 48 rows | **0.9949 (-0.51%)** |

Bootstrap 95% interval over rows: `[-0.98%, -0.09%]`. The weak 64 KiB rows move
most: `mr.64k` q6 -4.95%, `nci.64k` q11 -4.01%, `mr.64k` q11 -3.87%,
`mozilla.64k` q6 -3.81%, `xml.64k` q6 -3.19%, `nci.64k` q6 -3.19%.

Two large rows regress about 2%; an 8-round recheck confirms `nci.1m` q6 +1.75%
and `reymont.1m` q11 +1.96%, while `osdb.64k` q6 is +0.83%. A bisect shows the
regressions come from inlining the three tree lookups (the 64 KiB gains do too);
inlining only `readCommandSymbol` is neutral on all four probed rows. The 1 MiB
group geometric means remain neutral because other large rows improve.

This increment is below the default 3% geometric-mean bar; it is kept as a
target-row improvement for the command-dense 64 KiB rows, with every verified
control above the 0.98x floor.

## Next

- Cache the resolved command/literal/distance tree pointers per block type and
  update them on block switch, removing the per-symbol index checks without
  inlining the cold packed-tree expansion. This targets both the 64 KiB gains
  and the 1 MiB regressions from the inline experiment.
- Longer term, fuse the payload phase dispatch the way libbrotli's decoder does;
  the profile is flat across the per-command helpers, so only a restructure can
  close the remaining 1.2--1.7x gap.
